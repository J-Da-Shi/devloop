# DevLoop 设计系统

> 本文件是桌面端与手机端界面的统一视觉和交互基线。页面级规则如有差异，放在
> `design-system/devloop/pages/` 中，并只覆盖必要部分。

## 产品定位

DevLoop 是本地开发任务与 Agent 执行工作台，不是营销网站。界面优先支持快速扫描、
重复操作、状态比较和远程查看，避免超大标题、装饰性渐变、悬浮页面区块和多层卡片。

## 视觉基线

- 参考 Flova 深色创作工具的视觉语言，使用纯黑背景、半透明白色表面和清晰的前景层级。
- 主操作使用浅绿到白色的柔和过渡，选中态使用低透明度绿蓝过渡；成功、警告和危险色只表达状态。
- 不让页面被单一色系主导，状态必须同时使用文字、图标或形状表达。
- 卡片和对话框圆角不超过 `8px`，按钮圆角使用 `6px`。
- 使用白色透明度、轻微背景模糊和稳定间距建立层级，不使用模块编号制造科技感。
- 不使用装饰性光球、强烈霓虹、终端化小字或营销式大卡片；渐变只用于主操作和选中态。

## 颜色变量

| 用途       | 颜色或透明度                               |
| ---------- | ------------------------------------------ |
| 页面背景   | `#000000`                                  |
| 主内容背景 | `rgba(255, 255, 255, 0.045)`               |
| 抬升背景   | `rgba(255, 255, 255, 0.08)`                |
| 主要文字   | `#ffffff`                                  |
| 次要文字   | `rgba(255, 255, 255, 0.56)`                |
| 边框       | `rgba(255, 255, 255, 0.10)`                |
| 主操作     | `linear-gradient(90deg, #d2ffb3, #ffffff)` |
| 选中态     | 低透明度 `#81ff70` 到 `#559cff`            |
| 成功       | `#6ee7b7`                                  |
| 警告       | `#f5c96f`                                  |
| 危险       | `#fca5a5`                                  |

所有正文与背景的对比度至少满足 WCAG AA。正文信息不得使用低于 `56%` 的白色透明度。

## 字体

- 正文使用系统无衬线字体：`Inter, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`。
- 只让数值遥测、时间、日志、Commit 和路径使用系统等宽字体。
- 页面标题使用 `20px` 至 `24px`，紧凑面板标题使用 `15px` 至 `18px`。
- 不根据视口宽度缩放字体，字间距保持 `0`。

## 间距与尺寸

| 变量         | 尺寸    | 用途               |
| ------------ | ------- | ------------------ |
| 紧密间距     | `4px`   | 图标与状态点       |
| 小间距       | `8px`   | 同组控件           |
| 标准间距     | `16px`  | 面板内边距         |
| 大间距       | `24px`  | 页面区域间距       |
| 桌面侧栏     | `232px` | 主导航             |
| 桌面顶部栏   | `68px`  | 当前页面与全局操作 |
| 手机底部栏   | `64px`  | 主要路由入口       |
| 最小触控目标 | `44px`  | 手机按钮和图标操作 |

## 组件规则

### 按钮

- 图标能明确表达的工具操作只使用 Lucide 图标，并提供悬停提示和可访问名称。
- 创建、确认、通过等明确命令使用“图标 + 文字”。
- 危险操作必须显示确认对话框，提交期间禁用重复操作。
- 悬停只改变颜色、边框或阴影，不使用会引发布局变化的缩放动画。

### 卡片与区域

- 卡片只用于任务、项目、设备等可重复对象。
- 页面章节保持无框或全宽，不把卡片嵌套在卡片中。
- 运行日志和看板可以使用带边框的工具面板，但尺寸必须稳定。

### 表单

- 所有输入都有可见标签，错误信息紧邻对应字段。
- 使用受控表单状态，提交结果必须有明确成功或失败反馈。
- 手机端不开放本地目录、命令和安全能力配置，只允许受控领域字段编辑。

### 状态

- 实时状态区域使用 `aria-live="polite"`。
- 运行中同时显示状态点、阶段文字和更新时间。
- 离线状态必须明确标记为最后快照，不能让用户误认为数据仍在实时更新。

## 响应式规则

- 必须检查 `375px`、`768px`、`1024px` 和 `1440px` 视口。
- 手机默认进入执行状态页，首屏显示电脑在线状态、Worker、当前任务和待审核数量。
- 桌面使用侧栏；手机使用底部导航，并为正文预留安全区域。
- 表格在窄屏转换为列表或组件内部横向滚动，禁止页面级横向滚动。
- 看板列保持固定宽度，只允许看板容器内部横向滚动。
- 文本不得遮挡相邻内容；长路径、Commit 和日志允许换行或在局部容器内滚动。

## 动效与无障碍

- 颜色和透明度过渡控制在 `150ms` 至 `250ms`。
- 尊重 `prefers-reduced-motion`，关闭非必要动画。
- 键盘焦点始终可见，对话框支持焦点锁定和 Escape 关闭。
- 图标按钮必须有 `aria-label`，输入标签通过 `for` 与 `id` 关联。
- 颜色不是唯一状态标识。

## 交付检查

- 没有表情符号充当图标。
- 所有交互元素有清晰悬停、按下、禁用和焦点状态。
- 桌面与手机均无不合理遮挡或页面级横向滚动。
- 重要异步操作有加载、成功、失败和冲突反馈。
- 危险操作有确认步骤。
- 手机端可以查看执行情况并修改允许编辑的任务内容，但不能直接操作本地文件。
